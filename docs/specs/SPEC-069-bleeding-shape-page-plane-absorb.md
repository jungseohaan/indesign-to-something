# SPEC-069: 도련(bleed) 도형을 배경 평면에 흡수

> 상태: **머지 완료 (#142)**. 20페이지 회귀 PASS. 2026-07-24.
> 사례: 영어 u1 p10(1단원 도비라) — 보라색 도형이 원본보다 작게, 좌상단에 빈틈.
> 선행: [SPEC-068](SPEC-068-page-plane-foreign-visual-owner-hide.md) 이 중복을 제거하면서 드러남.

## 문제

플로팅 도형이 원본보다 작게 배치되고 좌상단에 빈틈이 생긴다. 영어 u1 p10 실측:

| 도형 | 원본 | 배치 | 손실 |
|---|---|---|---|
| 보라색 (1304) | 172.20 × 188.00 mm | 164.20 × 184.50 | 가로 8.00, 세로 3.50 |

보라색은 좌표가 `[-3.5, -8.0, ...]` 로 페이지 경계 **바깥까지** 그려져 있다(도련).
PNG 픽셀 자체는 온전한데 배치 상자만 잘린 값이라 그림이 좁은 틀에 우겨넣어진다.

## 원인

도련 도형은 **개별 PNG로 두는 한 반드시 깨진다.** HWPX 는 페이지 밖 배치를 지원하지
않기 때문이다. 실측으로 확인한 사실:

- 추출기 클램프와 Java `BackgroundInjector` 가 **각각 독립적으로** 도련을 자른다.
  한쪽만 고치면 다른 쪽이 되돌린다 (추출기만 수정 시 최종 HWPX 가 바이트 단위로 동일).
- 억지로 원본 크기를 넘기면 `horzOffset="-2268"` 같은 음수 오프셋이 나오는데,
  **한글이 이를 0 으로 밀어 넣어** 도형이 안쪽으로 밀리고 오히려 더 어긋난다.
  (XML 은 정상, 렌더러가 음수 미지원)

## 목표

도련 도형을 **배경 평면에 녹인다.** 배경 평면은 페이지 통째 export 라서 도련이
자연스럽게 처리된다 — 페이지 밖은 렌더 단계에서 잘리고 남은 그림은 페이지에 정확히
맞는다. 크롭 계산도 좌표 보정도 필요 없다.

## 해결 방안

**도련 유무를 직접 증거로 삼는다.** 레이어 이름·커버리지 같은 간접 추정 대신
"이 도형이 페이지 경계를 넘는가"라는 측정 가능한 사실로 판정한다.

`sourceIsBleedingBackdropShape` 조건:

- 페이지 밖으로 `BLEED_ABSORB_MIN_OVERHANG`(0.5mm) 초과 돌출
- 페이지와 실제로 겹침 (완전히 벗어난 것은 제외)
- **textless** — `sourceTreeHasEditableText` 로 하위 트리까지 검사
- 스토리 인라인/앵커 아님, 보이는 그래픽 있음
- 배경 레이어 이름은 이미 다른 경로가 처리하므로 제외

역할 이름은 `BLEEDING_TEXTLESS_PAGE_SHAPE`.

### textless 가 결정적인 이유

p10 에서 도련 도형은 셋인데 처리가 갈린다:

| 소스 | 도련 | 텍스트 | 처리 |
|---|---|---|---|
| 1304 보라색 | 위 3.5 / 왼쪽 8.0mm | 없음 | **흡수** |
| 19391 배경 | 사방 | 없음 | 이미 배경 소유 |
| 1578 흰 박스 | 아래 19.6mm | **있음** | **제외** |

흰 박스를 흡수하면 그 안의 `Functions`/`I'm glad we have...` 본문이 통째로 그림이
되어 편집 불가가 된다. textless 가드가 이를 막는다.

### 레이어 기준을 쓰지 않은 이유

초기에 "바탕 레이어 바로 위" 를 시도했으나 실패했다. IDML designmap 확인 결과
이 문서의 레이어 순서는 `가쇄용QR(0) / QR(1) / 하시라(2) / 헤드(3) / QR(도비라)(4) /
레이어1(5) / 헤드(바탕)(6) / 바탕(7)` 이고, 보라색이 있는 `헤드`(3)와 `바탕`(7)
사이에 **세 레이어가 끼어 있다**. 인접성은 안정적 관계가 아니다.

(참고: DOM `layerIndex` 는 위에서부터 0, IDML 문서 순서는 먼저 나온 것이 아래.
둘 다 `바탕` 이 최하단임을 가리킨다.)

## 주의사항

- **도련 도형을 개별 PNG 로 두면 반드시 깨진다.** 크롭·좌표 보정으로 해결하려 하지 말 것.
  한글이 음수 오프셋을 지원하지 않아 근본적으로 불가능하다
- **textless 가드를 빼지 말 것.** 텍스트를 담은 도련 프레임을 흡수하면 본문이 그림이 된다
- 레이어 인접성("바로 위")은 판정 기준으로 쓸 수 없다 — 미사용 작업 레이어가 사이에 낀다
